# 晴空卡丁车 · SUNNY KART

原创卡通竞速游戏，支持电脑与手机横屏。0.4 版包含晴空大环岛（2.14km）、糖果丘陵（1.75km）、晴风海湾（2.00km）和星光峡谷（2.03km），各有不同路线、环境、地标和加速节奏。在主菜单点击“换条赛道”选择，也可“航拍全图”查看。竞速赛专注漂移和氮气，道具赛增加五种手动道具；轻度碰撞推挤、减速，不翻车。支持单人对 AI 和 2–8 人好友房间，以及个人计时挑战与最佳幽灵。

## 开始游戏

[在线游玩 · GitHub Pages](https://rxl333.github.io/sunny-kart/) · [项目源码](https://github.com/RXL333/sunny-kart)

Windows 双击 **启动游戏.cmd**，浏览器会打开 `http://localhost:3001`。需要已安装 Node.js；本机已经安装。首次缺少依赖时脚本会运行 npm ci。脚本在后台启动游戏服务，日志位于 logs/。

也可在项目目录运行：

```powershell
npm ci
npm run build
npm start
```

开发时分别运行 `npm run dev` 和 `npm run dev:server`，浏览器访问 Vite 显示的 5173 地址。修改源码后需重新 `npm run build` 才会反映到 3001 生产页面。

## 本次体验升级

- 金色氮气晶体拾取后有吸收粒子、音效和氮气条反馈，本车本圈内消失，下一圈刷新，不能反复领取。满氮气仍可收集，提示已满。
- 主菜单选择 **竞速赛 / 道具赛**，好友房间由房主创建时决定，所有成员同步模式；竞速赛不出现道具箱。
- 道具赛经过彩色箱子存入一个道具，按 **E** 或手机 **✦ 道具键** 使用。满槽不替换，长按只使用一次。**泡泡护盾**持续 7 秒并抵挡一次道具攻击；**能量磁铁**持续 8 秒，扩大晶体拾取范围；**火箭冲刺**持续 2.8 秒；**泡泡弹**向前发射，**果冻陷阱**放在身后。攻击只减速约 1 秒，受击保护持续 2 秒，始终保留驾驶控制。后排较容易获得追赶道具，AI 与玩家使用同一规则。
- 主菜单的 **计时挑战**提供单车三圈比赛，没有 AI、碰撞和随机道具。显示分圈成绩、个人最佳幽灵和领先／落后时间；最佳记录按赛道、角色和物理版本独立保存。
- 好友房间支持 30 秒内断线恢复原席位，期间由 AI 暂代；服务器重启后内存房间仍会丢失。同步改为确认输入重放与远端快照插值，不能消除真实网络往返延迟。
- 模型跨赛道复用，未加载完成时可先使用内置赛车；粒子使用对象池，小地图缓存路线，自动画质根据持续帧耗时调整。

前后端需一起更新。协议 v4 校验模式、手动道具和恢复能力，旧客户端会提示刷新，前端遇旧服务器会提示等待更新，单人游戏仍可使用。后端重启会清空内存房间。

本次修改范围、测试结果与云端性能实测见 `docs/云端体验优化与验收.md`。

### 浏览器回归与性能记录

```bash
npm test
npm run test:e2e
npm run perf:browser
```

浏览器测试使用当前云机器的 Chromium（若存在）；其他机器首次需运行 `npx playwright install --with-deps chromium`。可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定浏览器。E2E 自动启动独立的 4180/4181 服务；性能脚本使用 4183，需先完成生产构建。报告和截图保存在忽略目录 `logs/`。云端 SwiftShader 是软件 WebGL，测得帧率不能代表手机 GPU；iOS／Android 真机仍需补验。

专用开发 E2E 服务使用 `VITE_E2E=1` 布置稀有拾取和完赛状态；该辅助接口仅在 Vite 开发模式启用，生产构建不包含。常规驾驶、设置和双页面联机测试直接操作真实界面。CI 在 Pages 部署前执行浏览器回归并保留失败证据。

## 操作

游戏会按设备的指针能力和实际输入识别电脑或触控模式，电脑窗口变窄也保留键盘提示。电脑主菜单和比赛底部显示各功能当前键位；右上角 **⚙ 游戏设置 → 电脑键盘** 可修改加速、刹车、转向、漂移、氮气、使用道具、自动油门、暂停和重赛的主键及副键。点击待改的键，再按新键，立即应用并保存在本浏览器；界面与帮助说明同步更新。占用的键会提示冲突，Esc 取消录制，“恢复默认键位”保留手机布局。下表是初始默认键位。

手机建议横屏游玩。左侧转向，右侧漂移、氮气、刹车和油门；手机默认自动油门，可在 HUD 或设置里关闭。右上角 **⚙ 游戏设置** 可选择左右手布局，调整转向灵敏度、按键大小、不透明度、离底部距离、画面质量和音量；设置自动保存在本机，也可恢复默认。支持多指同时按住与方向键滑动切换。

设置内的 **自定义按键位置** 可逐个拖动七个触屏按键，点击“保存布局”后应用并保存在本浏览器；“取消”保留原布局，“恢复预设”清除当前方向的草稿。横竖屏分别记录位置，改变屏幕尺寸后会钳制在安全区内；布局重叠时提示分开。旧版六键和九项键盘映射会迁移保留，E 已被占用时道具键使用空闲按键。切换左右手预设或恢复默认设置会清除自定义位置。

游戏画布、HUD 和按键会抑制长按菜单、文字选择、原生拖拽以及误触缩放/滚动。输入框、房间号复制与设置面板滚动保留；浏览器和系统级手势仍由设备决定。

手机提供全屏入口和横屏提示；浏览器不支持方向锁时，请手动旋转。单人出现竖屏提示或打开设置会暂停，关闭后接着原进度继续；联机中不会暂停其他玩家，遮罩打开时本车制动。

| 按键 | 动作 |
| --- | --- |
| W / ↑ | 油门 |
| S / ↓ | 制动 |
| A D / ← → | 左右转向 |
| Shift + 转向 | 漂移蓄力，松开后小喷并补氮；反向转向可以收回侧滑 |
| Space / N | 持续释放氮气 |
| E | 使用持有道具（道具赛） |
| Q | 自动油门开关 |
| Esc | 单人暂停 / 继续 |
| R | 单人重新比赛 |

赛道上的金色晶体补充氮气，青色箭头加速带提供短时加速。每场三圈，七位 AI 补齐八车。

## 好友联机

同一局域网的朋友用浏览器访问这台电脑的局域网 IP，例如 `http://电脑的局域网IP:3001`。一人点击“好友联机 → 创建房间”，其他人输入六位房间码，至少两人加入后房主开始。使用相同服务地址才能看到同一个房间。系统防火墙如阻拦需由用户允许该服务在对应网络通信。

房主创建房间时确定赛道，加入者自动采用相同路线。旧版本客户端可继续使用经典大环岛；加入新赛道房间时会提示刷新，避免两端地图不同。

服务器 60Hz 统一模拟、20Hz 发送快照；客户端 30Hz 发送输入，做本地预测与位置平滑，显示实测往返延迟。断线车辆由 AI 接管，房主离开自动移交。联机不暂停整个比赛，离开可以返回主菜单。

公网后端已部署到 [Render Free](https://sunny-kart-server.onrender.com/health)，Pages 已接入好友联机。两个浏览器页面的创建、加入、开赛与加速已验证。当前测试线路往返延迟波动较大，独立设备和长期游玩体验仍待验收；单人模式在本地模拟，不依赖联机延迟。

GitHub Pages 与后端分开部署的构建、环境变量和免费主机限制见 `docs/部署配置.md`。后端 endpoint 通过仓库 Actions variable `VITE_SERVER_URL` 配置；Pages 上不把 github.io 当作 WebSocket 服务器。新赛道与物理的实现、验收和部署范围见 `docs/地图物理升级.md`。

## 源文件与检查

- `assets/source/kart*.blend`：三位车手及赛车的可编辑 Blender 源。
- `assets/source/build_kart.py`：程序化建模脚本。
- `public/models/`：原创 GLB 运行资产，每车低于 25k 三角面。
- `npm test`：竞速规则与真实 WebSocket 集成测试。
- `node scripts/check-public-server.mjs https://sunny-kart-server.onrender.com`：可选的真实公网双连接冒烟检查，会创建并清理自己的测试房间。
- `docs/实施计划.md`、`docs/测试报告.md`：需求依据、完成范围与真实验证状态。
- `docs/手机横屏适配.md`：手机与自定义设置的实现、尺寸检查和真机待验收项。
- `docs/0.3测试与发布说明.md`：多赛道、自由拖动按键、浏览器手势防护与本次验证边界。
- `docs/电脑键位与设备设置计划.md`、`docs/0.3.1键位适配验收.md`：电脑改键、设备识别和实际验证状态。
