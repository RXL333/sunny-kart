# 前后端分开部署

前端已发布到 [GitHub Pages](https://rxl333.github.io/sunny-kart/)；权威联机服务使用用户确认的 Render Free Node.js WebSocket 主机。源码为 [RXL333/sunny-kart](https://github.com/RXL333/sunny-kart)。

## 构建变量

| 名称 | 用途 |
| --- | --- |
| `VITE_BASE_PATH` | Pages URL 的路径，以 `/` 开头并结尾。留空时脚本根据 `GITHUB_REPOSITORY` 自动推导；用户站点仓库为 `/`，普通项目仓库为 `/<仓库名>/`。 |
| `VITE_SERVER_URL` | 公开 HTTPS 后端地址或完整 WSS 地址，不含账号、密码、密钥。仓库 Actions variable 使用相同名称。 |
| `PORT` | Node 后端监听端口，由主机注入；本地/容器默认 3001。 |

`scripts/build-pages.mjs` 验证环境变量并运行 Vite 构建，写入 `dist/.nojekyll`。Vite 配置需读取 `process.env.VITE_BASE_PATH`；模型等运行时路径需使用 `import.meta.env.BASE_URL`。后端连接需读取 `import.meta.env.VITE_SERVER_URL`，不能在 Pages 上连接 github.io 的 `/ws`。

`.github/workflows/deploy-pages.yml` 在 main 推送或手动运行时安装锁定依赖、运行测试、生成 artifact，再由独立最小权限任务部署 Pages。仓库 Pages source 需设为 GitHub Actions。Actions 已锁定官方发布的 commit SHA。

## 容器后端

Dockerfile 只拷贝 package、server 和共享 game 规则，运行 `node server/index.js`。镜像包含健康检查 `/health`，不包含本地日志、Blender 源文件、截图、个人环境文件或前端资产。前端资产由 GitHub Pages 提供；容器根路径无需承载前端。

## Render 部署

仓库根目录的 `render.yaml` 使用免费 Web Service、Singapore 区域、Node 24，构建 `npm ci --omit=dev`，启动 `node server/index.js`，健康检查 `/health`。配置不要求数据库、磁盘或付费实例。

[在 Render 部署公开仓库](https://render.com/deploy?repo=https://github.com/RXL333/sunny-kart)。登录后检查配置并部署，服务上线后把实际 HTTPS 地址写入仓库 Actions variable `VITE_SERVER_URL`，重新运行 Pages 工作流。

后端默认最多32连接、8房间；创建房间限频，处理慢客户端背压、心跳失联和闲置房间清理，可通过环境变量调整。

Render 免费实例15分钟没有HTTP请求或WebSocket消息会休眠，重新唤醒约需1分钟；内存房间会在重启时丢失。客户端先请求健康检查并显示唤醒状态，避免把冷启动误报为立即连接失败。

官方依据：[Vite Pages 部署](https://vite.dev/guide/static-deploy.html#github-pages)、[GitHub Pages artifact 部署](https://github.com/actions/deploy-pages)、[Render 一键部署](https://render.com/docs/deploy-to-render)、[Render 免费限制](https://render.com/docs/free)、[Render WebSocket](https://render.com/docs/websocket)。
