# 前后端分开部署

前端发布到 GitHub Pages；权威联机服务使用独立 Node.js WebSocket 主机。此配置没有替用户选择或建立后端收费方案。

## 构建变量

| 名称 | 用途 |
| --- | --- |
| `VITE_BASE_PATH` | Pages URL 的路径，以 `/` 开头并结尾。留空时脚本根据 `GITHUB_REPOSITORY` 自动推导；用户站点仓库为 `/`，普通项目仓库为 `/<仓库名>/`。 |
| `VITE_SERVER_URL` | 公开 HTTPS 后端地址或完整 WSS 地址，不含账号、密码、密钥。仓库 Actions variable 使用相同名称。 |
| `PORT` | Node 后端监听端口，由主机注入；本地/容器默认 3001。 |

`scripts/build-pages.mjs` 验证环境变量并运行 Vite 构建，写入 `dist/.nojekyll`。Vite 配置需读取 `process.env.VITE_BASE_PATH`；模型等运行时路径需使用 `import.meta.env.BASE_URL`。后端连接需读取 `import.meta.env.VITE_SERVER_URL`，不能在 Pages 上连接 github.io 的 `/ws`。

`.github/workflows/deploy-pages.yml` 在 main 推送或手动运行时安装锁定依赖、运行测试、生成 artifact，再由独立最小权限任务部署 Pages。仓库 Pages source 需设为 GitHub Actions。Actions 已锁定官方发布的 commit SHA。

## 容器后端

Dockerfile 只拷贝 package、server 和共享 game 规则，运行 `node server/index.js`。镜像包含健康检查 `/health`，不包含本地日志、Blender 源文件、截图、个人环境文件或前端资产。前端资产由 GitHub Pages 提供；容器根路径无需承载前端。

## 免费主机的实际限制

平台尚待原对话信息确认。已核对的备选事实：

- Render Free Web Service 可直接运行目前的 Node HTTP/WebSocket 服务；15 分钟没有 HTTP 请求或 WebSocket 消息会休眠，重新唤醒约需 1 分钟。每 workspace 每月有 750 小时，临时文件和内存房间会在重启时丢失。免费服务不提供始终在线或延迟保证。
- Cloudflare Durable Objects 的 SQLite 存储类别有 Free 方案，适合有状态 WebSocket；它使用 Workers/DO 运行时，当前 Node `http` + `ws` 服务需要迁移，不能直接用同一 Dockerfile 部署到 Workers Free。

这些限制来自当前官方资料，不能据此认定这就是原对话已选平台。

官方依据：[Vite Pages 部署](https://vite.dev/guide/static-deploy.html#github-pages)、[GitHub Pages artifact 部署](https://github.com/actions/deploy-pages)、[Render 免费限制](https://render.com/docs/free)、[Render WebSocket](https://render.com/docs/websocket)、[Cloudflare Durable Objects 价格与额度](https://developers.cloudflare.com/durable-objects/platform/pricing/)。
