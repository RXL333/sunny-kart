# 晴空卡丁车首版测试报告

日期：2026-10-20。电脑网页端；本机 Windows、Node.js v24.11.1、Chromium 浏览器。

## 最终结果

- `npm run build`：通过。生产资源位于 dist/。
- `npm test`：14 项通过，0 失败、0 跳过；约 4.2 秒。
- `start-game.ps1 -NoBrowser`：通过，后台 Node 服务成功启动，`127.0.0.1:3001/health` 返回 ok=true。
- 生产页面 `http://localhost:3001`：已实际加载菜单、三个角色模型并创建好友房间。

## 自动测试覆盖

1. 闭合赛道、单位切线及右侧法线。
2. 无油门不前进，制动不会倒刷圈。
3. 倒计时/比赛暂停冻结，继续保留状态，重开清零。
4. 漂移松手加速及补氮，主动氮气消耗。
5. 按完整累计距离计圈，三圈结算与名次排序。
6. 多个人类玩家输入隔离，快照保留本地身份。
7. AI 能完赛，轻度碰撞状态保持有限值。
8. 第二位玩家收到属于自己的漂移事件。
9. 两个真实 WebSocket 客户端创建/加入六位房间、房主权限、权威位置更新、断线转 AI、房主移交、ping 和静态路径越界防护。
10–12. 狐狸、兔子、熊猫模型合批前后包围盒误差为零；四个轮组枢轴与换色材质保留。
13. 输入最多 30Hz，仅比赛中发送；离开、大厅和已结束状态不发输入。
14. 建立连接及并发创建/加入等待 welcome 身份，名字使用真实连接 ID 后缀。

## 浏览器实测通过

- 桌面 1440×900、1280×720 与窄屏 390×667 菜单；角色选择与三维模型同步切换。
- 单人从倒计时到完整三圈、结算、个人最佳保存。
- 自动油门、键盘转向、Shift 漂移释放加速、空格氮气。
- 单人暂停：计时在 00:04.93 保持不变；继续后恢复。
- 两个浏览器客户端分别作为狐狸与熊猫加入同一房间，同时倒计时，各自镜头跟随本人。
- 双人真实完赛：熊猫 00:47.80、狐狸 00:51.78；两端排行榜相同，均正确标记本人。
- 另实测超时未完赛场景，显示“未完赛”，没有伪造完赛时间。
- 非房主点击重赛提示等待，房主可在原房间发起下一场，两端同步重开。
- 联机空格实测：氮气 100% 降至 78%，速度约 170km/h；本机观测 RTT 约 2–14ms，仅代表本机两客户端。
- 开发版最终浏览器日志无运行错误；生产版房间成功连接，模型与资源正常显示。
- 生产启动脚本最初遇到 localhost 的 IPv6 回退使健康检测超时，已将检测改为 127.0.0.1，重新启动实测成功。

## 美术验证

三位车手均为原创 Blender 模型，每个低于 25k 三角面。保留 .blend、生成脚本、GLB 与渲染预览。实时 Blender 场景已显示狐狸卡丁车，原场景保留。

运行时按材质合并模型：狐狸/兔子 116/114 个网格降至 16 个，熊猫 113 个降至 15 个，保留轮子旋转；这验证了结构优化，不等于已经测出所有硬件上的帧率。
