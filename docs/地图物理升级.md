# 0.2 地图、物理与公开部署

## 本轮需求
用户认为地图太小，要求扩大地图、继续优化碰撞等物理，并部署 GitHub Pages。用户已确认免费后端采用 Render。后续反馈要求修正左右反向、改善碰撞音效并复查驾驶体验。

## 实现
- 赛道由约593米增加至2135.5米，路宽16米，覆盖范围635.9×510.0米，约原地图十倍面积。
- 晴风海岸、薄荷森林、云顶山道、浮光海湾和橘子小镇五段，9条加速带、96枚能量晶体；最高约26米的起伏与跨海桥。
- 空间网格查询和16块地形；树木、路缘、护栏、花石实例化。相机、视距、阴影随场景变化；增加航拍全图。
- 1/120秒子步长，共享给浏览器与服务器。速度相关转向、侧向速度、漂移抓地与惯性、曲率外甩、坡道阻力和渐变草地阻力。
- 车体由前后两圆组成，在真实世界XZ坐标求解接触冲量、摩擦和位置纠正；轻度碰撞耗能，不翻车。急弯内外侧、追尾、侧向接触和整车护栏范围均覆盖。
- 客户端预测使用相同子步长，服务端确认事件后才播放奖励反馈；新地图成绩独立存储，避免原短赛道纪录污染。
- Pages 子路径模型加载、公开HTTPS/WSS后端配置、健康检查唤醒与连接中取消请求；本地运行继续可用。
- 修正键盘与触屏左右输入，使用实际跟车镜头投影验证方向；碰撞音效改为低通短噪声和低频闷响，限制音量与连续触发。

## 验收与部署次序
1. 跑驾驶、碰撞、地图地形、真实WS、URL与请求取消回归。
2. 浏览器检查航拍和实际驾驶，确认小地图、区域名、资源路径与物理表现。
3. 生产构建、检查待发布文件，创建Git仓库和公开GitHub项目。
4. GitHub Actions在测试通过后部署Pages，检查实际公网URL和模型资源。
5. 确定免费后端平台并取得已有账号访问后部署权威服务，配置WSS endpoint，再验证两客户端公网房间与往返延迟。

不把本地结果作为公网结果，不把待用户输入或认证的后端步骤写成已完成。
